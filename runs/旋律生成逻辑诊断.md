# 旋律生成逻辑诊断：每个音符到底是怎么算出来的

> 对象：`compose_kernel.py` 的 `melody` 脚本（`_s_melody`，1606–1877 行）
> 实测产物：`scores/chats/destiny_v5.json`（命运交响曲，32 小节 / 14 声部，旋律 = Flute）
> 诊断日期：2026-09-28

---

## 0. 一句话结论

**第一个音符不是随机的，第二个、第三个也不是。整条旋律里唯一的随机点，是「每小节挑哪条节奏模板」。**
音高是**确定性**算出来的，而且素材只有一处来源——**本小节和弦的那 3–4 个音**。
所以你听到的「复制粘贴」，不是随机没随好，是**可选集合本来就只有 3 个音，还被一条贪心打分规则反复选出同一条最短路**。

## 2. 逐音推导（手算验证，与实跑输出逐音相符）

取 c 小调、`register=high`（center=79，窗口 70–89）、`contour=arch`、4/4、节奏固定为 4 个四分音符。

### 第 1 小节：和弦 = i（C Eb G），target = 79 + 0 = **79**

**第 1 个音**（`a_prev is None`，走 1776–1779 的「起头」分支）：

```
候选 = 和弦音映射到本音区：C→84、Eb→75、G→79
取 |候选 − target| 最小者 → G(79)，|79−79| = 0
→ 第 1 音 = G5
```
**所以第一个音是「本小节和弦音里离乐句目标最近的那个」，一步都不随机。**

**第 2 个音**（`a_prev=79`，走 1780–1799 的打分分支）：

```
候选 cands = {C→84, Eb→75, G→79}
tier1 硬过滤：≠上一音(79)、≠前两音(None)、|Δ| ≤7  →  {84, 75}
score(m) = 0.6×|m − 上一音| + |m − target|
           + (目标在上却往下走 ? +4 : 0) + (目标在下却往上走 ? +4 : 0)
  score(84) = 0.6×5 + 5 = 8.0
  score(75) = 0.6×4 + 4 = 6.4   ← 最小
→ 第 2 音 = Eb5
```

**第 3 个音**（`a_prev=75`，`a_back=79`）：

```
cands = {C→72, Eb→75, G→79}
tier1：≠75、≠79、|Δ|≤7 → 只剩 {72}   ← 只剩一个候选，被迫
→ 第 3 音 = C5
```

**第 4 个音**（`a_prev=72`，`a_back=75`）：

```
cands = {C→72, Eb→75, G→79}      （G 的 67 超出下界 70，被 +12 提到 79）
tier1：≠72、≠75、|Δ|≤7 → 只剩 {79}
→ 第 4 音 = G5
```

实跑输出：`第1小节: G E- C G` —— **四音全部吻合**。

### 第 2 小节：和弦 = iv（F Ab C），target = 79 + 2 = **81**

跨小节继承：`prev_midi=79(G)`、`back1=72(C)` 原样带过来。

```
第1音: cands={F→77, Ab→80, C→84}
       tier1 全过 → score(77)=1.2+4=5.2  score(80)=0.6+1=1.6  score(84)=3+3=6
       → Ab5(80)
第2音: a_prev=80, a_back=79 → tier1 排除 80 与 79，剩 {77, 84}
       score(77)=1.8+4=5.8  score(84)=2.4+3=5.4 → C6(84)
第3音: a_prev=84, a_back=80 → tier1 只剩 {89} → F6
第4音: 同理 → C6
```
实跑输出：`第2小节: A- C F C` —— **吻合**。

### 弱拍（时值 <1 拍）

不是锚点，走 1824–1843：
```
direction = 下一锚点在前 ? +1 : −1
m = _scale_step_to(当前音, direction, lo, hi, 调内音)
   = 沿音阶朝下一锚点走一步（纯确定性，无随机）
走过头 → 直接落到锚点；走不动 → 反向一步
```
**即：弱拍只能是级进经过音，永远不能跳进、不能装饰、不能重复动机。**

## 3. 随机性到底在哪（实测）

| 实验 | 做法 | 结果 |
|---|---|---|
| A | 固定节奏模板为 `[1,1,1,1]`，**关掉叙事层**，换 3 个 seed | 三份旋律**逐音完全相同** |

## 4. 量化：为什么听起来是「复制粘贴」

### 4.1 素材面只有 3–4 个音

用 `sys.settrace` 抓 `_s_melody` 内部真实变量（`m = min(pool, key=_score)` 那一行），16 小节共 **63 次锚点决策**：

| 指标 | 实测 |
|---|---|
| 候选音个数（= 本小节和弦音） | 恒为 3–4 个 |
| 过滤后**只剩 1 个可选** | **20/63 = 31.7%** |
| 2 选 1 | 30/63 = 47.6% |
| 3 选 1 | 12/63 = 19.0% |
| 4 选 1 | 1/63 = 1.6% |
| tier1 为空、被迫放宽到 tier2 | 7/63 = 11.1% |
| 纯路径下旋律音落在和弦音上 | **100%** |

### 4.2 打分函数是「贪心最短路」→ 产出琶音而不是旋律

纯路径（全四分音符）16 小节的相邻音程分布：

```
1 半音: 7    2 半音: 4    3 半音: 15   4 半音: 11   5 半音: 11
6: 1        7: 7         8: 3         12: 1        23: 1
```
- 三/四/五度跳进（3–5 半音）：**44/60 = 73%**
- 级进（1–2 半音）：**11/60 = 18%**
- 16 小节只用 **14 个不同音高**

`0.6×|Δ| + |到目标|` 这项打分永远奖励「离上一音近、离目标近」，配合只有 3 个候选，结果就是**在小三和弦里来回走最短路**——听感上就是琶音。

### 4.3 和声循环把素材再砍一刀

`_s_set_harmony` 1052 行：`st.harmony[bar] = chords[i % len(chords)]`
——**进行长度短于段落小节数时整段循环**。

真实产物 `destiny_v5` 的 32 小节和声分布：

| 和弦 | 出现小节 | 占比 |
|---|---|---|
| `C Eb G`（主） | 1,2,4,5,8,15,18,19,22,23,24,26,30,32 | **14/32 = 43.8%** |
| `G B D F`（属七） | 3,7,17,21,25,28,29,31 | **8/32 = 25.0%** |
| `F Ab C` | 6,16,20,27 | 12.5% |
| `Eb G Bb` | 9,11,14 | 9.4% |
| `Bb D F Ab` | 10,13 | 6.3% |
| `Ab C Eb` | 12 | 3.1% |

**32 小节只有 6 种和弦，主和弦独占 43.8%。** 也就是说 14 个小节的旋律素材完全一样、都是 {C,Eb,G} 这 3 个音。

### 4.4 真实产物 `destiny_v5` 的旋律统计

| 指标 | 全曲 | 排除加厚段（15–22 小节） |
|---|---|---|
| 旋律音数 | 180 | 104 |
| 不同音高 | **21** | **16** |
| 落在本小节和弦音上 | **125/180 = 69.4%** | — |
| 小节首音落和弦音 | 23/32 = 71.9% | — |
| 级进（1–2 半音） | 22.3% | 38.8% |
| 跳进（3–4 半音） | 14.5% | 25.2% |
| 大跳（≥5 半音） | 52.5%（含 **50 个八度跳**） | 17.5% |
| 3-音型重复率 | 46/178 = **25.8%** | — |

> 说明：50 个八度跳**不是**旋律生成器的锅，主要来自高潮加厚（15–22 小节成对音符的八度叠置，见 `Ab Ab C C Ab Ab Bb Bb`）。排除后级进率升到 38.8%——但仍远低于真正的歌唱性旋律（通常 60–75%）。

## 5. 根因排序

1. **素材 = 本小节和弦音（3–4 个）**。这是最硬的上限：小节内无论写几个音，都只能在这 3–4 个音里打转。实测 100%（纯路径）/ 69.4%（真实产物）。
2. **候选池被过滤后经常只剩 1 个**（31.7%）。不是「选得像」，是「没得选」。
3. **打分函数是贪心最短路**，产出三/四/五度来回的琶音轮廓，缺少级进线条与高点布局。
4. **和声本身太窄且会循环**（32 小节 6 种和弦、主和弦占 43.8%；`i % len(chords)` 循环）。素材面被和声二次压缩。
5. **乐句之间没有句法关系**。现在 4 小节一句，第 2 句和第 1 句用**同一套规则**、只有 target 曲线相位差一格——没有模进、没有问答、没有倒影、没有「重复后变化」。
6. **弱拍只能做级进经过音**，没有跳进装饰、没有倚音/延留、没有音型贯穿。

## 6. 修复方向（按性价比排序）

| # | 方向 | 做法 | 影响面 |
|---|---|---|---|
| 1 | **扩素材面** | 候选从 `和弦音` 扩为 `和弦音 ∪ 可用张力音(七/九/十一) ∪ 调内邻音`，按协和度分层给权重；引入延留音（4→3、9→8、7→6）与倚音 | 改内核，需刷新 31 个风格指纹 + 全量测试；`test_narrative_key_safety` 需回归（防调外音） |
| 2 | **节奏动机贯穿** | 每小节从「动机节奏的变形池」（augment / diminish / fragment / 逆型）抽，而不是从通用模板池抽。这才是「三短一长无处不在」的命运式写法 | 改 `_pick_rhythm` 调用侧；同样需刷指纹 |
| 3 | **乐句句法** | 按乐句号套用算子：模进（±2/±3 度）、倒影、逆行、问答（前 2 小节重复 + 后 2 小节变化）、紧缩 | 改 `_s_melody` 的 phrase 循环；需刷指纹 |
| 4 | **目标导向解决** | `target` 从「8 项曲线循环」改为「朝下一个终止点的和弦音做倾向性解决」（导音→主音、七音→三音） | 改 target 计算；需刷指纹 |
| 5 | **和声多样性** | 32 小节 6 种和弦太窄。可在内核侧对连续同和弦做填充（i–i → i–vii°7/i–i），或在 `translator.md` 加约束让翻译器写更长的进行 | 只改提示词的最低风险；改内核则需刷指纹 |

**建议顺序**：5 → 2 → 1 → 3 → 4。
5 不动内核、可立刻用现有提示词验证效果；2 直接消灭「节奏层面的一模一样」；1 是治本；3/4 是锦上添花。

## 7. 附录：素材面从哪来

「素材面」指每小节旋律真正能取到的音高集合。它有三个来源，汇合后就是天花板。

### 7.1 和弦进行（主来源，决定强拍锚点）

```
用户提示词
  → planner（段落/情绪/速度）
  → translator（LLM 写内核调用）: set_harmony(section, progression=['i','i','V7','i','i','iv','V7','i'])
  → apply_style_quality       （有风格契约时随机加品质后缀；无契约 903 行直接返回）
  → parse_roman               （compose_kernel.py:198）罗马数字 → 音名
  → st.harmony[bar] = chords[i % len(chords)]   （1052 行，循环）
  → _s_melody: pcs = [_pc(n) for n in chord]    ← 素材面就是这 3–4 个音
```

`parse_roman` 的**音程表是写死的**（216–230 行）：

| 后缀 | 音程 | 音数 |
|---|---|---|
| 空（大写） | 0,4,7 | 3 |
| 空（小写） | 0,3,7 | 3 |
| `7` | 0,4,7,10 / 0,3,7,10 | 4 |
| `maj7` | 0,4,7,11 | 4 |
| `°7` / `ø7` | 0,3,6,9 / 0,3,6,10 | 4 |

**所以一个小节的强拍素材最多 4 个音，三和弦时只有 3 个。**

**无 LLM 时的骨架兜底**（`style_skeleton._harmony_pool`，418–422 行）更窄：
读风格包 `meta.yaml` 的 `harmony.progressions`，读不到就硬编码
`['I','vi','IV','V7']`（大调）/ `['i','VI','III','VII']`（小调），
再 `prog = [base[j % len(base)] for j in range(n_bars)]` —— **4 个和弦循环铺满整段**。

### 7.2 调内音阶（决定弱拍经过音）

`st.scale_for(sec)` → `_scale_names(sharps, mode)`（181–189 行）→
`m21scale.MinorScale` / `MajorScale` → **自然**大小调 7 个音。
c 小调 = `C D Eb F G Ab Bb`（没有和声小调的导音 B 还原，B 只在 V7 和弦里出现）。
弱拍的 `_scale_step_to` 只能在这 7 个音上走。

### 7.3 音区窗口（决定用哪个八度）

`REGISTER_CENTERS = {low:62, mid:71, high:79, very_high:84}`（32 行，4 档写死），
`lo,hi = center-9, center+10`；旋律路由到具体乐器时再被
`_fit_register_window` 收进该乐器音域。

### 7.4 命运交响曲的实测素材面

| 项 | 值 |
|---|---|
| 32 小节用到的不同和弦 | **6 种** |
| 全部和弦音的音级集合 | `{0,2,3,5,7,8,10,11}` = **8 个** |
| 调内音音级集合（c 小调 ∪ Eb 大调） | `{0,2,3,5,7,8,10}` = 7 个 |
| **素材面（并集）** | **8 / 12 个半音**（缺 C#、D#、F#、A） |
| 旋律实际用到的音级 | **8 个，与素材面相同** |
| 素材面里没用上的音级 | **空集** |
| 旋律用到的不同 midi 音高 | 21（8 个音级 × 约 3 个八度） |

**关键结论：旋律已经把素材面用尽了**（未用音级 = 空集），
再怎么调打分函数也变不出新音。要突破只能**扩大素材面本身**——
即修复方向 1（和弦音 ∪ 张力音 ∪ 邻音）和方向 5（让进行更长、更不重复）。

各段 progression（从成品 harmony 反推，罗马数字按各段调性）：

| 段 | 小节 | 进行 |
|---|---|---|
| A 呈示部 | 1–8 | `i i V7 i i iv V7 i` |
| B 副题（第 9 小节转 Eb 大调） | 9–14 | `I V7 I IV V7 I` |
| C 展开部 | 15–22 | `i iv V7 i i iv V7 i` |
| D 再现 | 23–28 | `i i V7 i iv V7` |
| E 尾声 | 29–32 | `V7 i V7 i` |

每段只用 3–4 个不同和弦，正是 6 种和弦铺满 32 小节的原因。
