# ComposerChat / Score Studio

**English** | [中文](README.zh-CN.md)

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)

A PyQt5 workbench for **deterministic symbolic music composition**: describe a piece in natural language (or use purely deterministic commands) and get an **editable score**. Every step is rule-checked, every note is reproducible, the generation process is auditable, and no training data is required.

> In one line: **deterministic kernel + LLM front end + rule checking + reproducibility + fugue engine**. We are not aware of a product with the same design (see `docs/对比分析_符号音乐调研报告.md`, in Chinese).

## What it does

| Capability | Description |
|------------|-------------|
| **Reproducible** | The same `seed` / `subseeds` always yields the same piece; `spec.json` is the reproduction record |
| **Guaranteed structure** | Full measures, cadences, legal counterpoint, musically correct leading-tone spelling |
| **Visual staff editing** | Add, change and delete notes directly on the score, with AI-style suggestions and three-level live checking (see "Score editor") |
| **Fugue engine** | Whole fugues on request (`/fugue full`) or inserted fugal sections; the LLM may not add a fugue the brief did not ask for (enforced by deterministic removal) |
| **Section-level modulation** | `set_harmony` accepts `key_sharps`/`mode`; a modulating B section is written into MusicXML `<key><mode>` |
| **Piano grand staff** | Two-voice piano is merged into one part with two staves (`<staves>2</staves>` + brace) |
| **Auditable** | Per-rule counts in the notation `RuleLog`; three metrics quantify style fit; prompt → score → analysis-report consistency tests |
| **No training data** | Rule/algorithm driven: no copyright risk, no hallucinated notes, nothing irreproducible |

## Architecture

```
natural language / commands
   │
   ▼
style_routing  two-level routing (family → pack, Chinese synonym normalisation, raises StyleRoutingError on failure)
   │
   ▼
style_skeleton style skeleton (inject profile → deterministic script call sequence)
   │
   ▼
compose_kernel deterministic kernel (derive_subseeds + soft weights + branched random sources)
   │
   ▼
notation       notation layer (spelling / beaming / ties / leading tones, RuleLog audit)
   │
   ▼
validate_score_spec + evaluate (three metrics: style_overlap / style_rank / attribute_adherence)
   │
   ▼
score_studio (PyQt5 UI) · deliver (LilyPond / runs archive) · MusicXML / MIDI
```

  - `Look up a command/feature…` shows a single entry;

  - `Reference manual` opens `runs/help_pro.md` in the system default app.
  - In the chat, `/help` shows the full catalogue and `/help <command or feature>` a single entry.
- **Reference manual `runs/help_pro.md`** (generated by `python gen_help_pro.py`): every command/feature is shown as **real input → actual output → verification**; deterministic commands are actually executed and checked by built-in assertions, with a test-result summary table at the end.

```bash
pip install -r requirements.txt
# Windows

./start_studio.sh
```

Main entry point: `score_studio.py` (or `start.bat`). An LLM API is needed for chat composition (see `llm_config.example.json`); without one, use `/demo` and the deterministic commands.


## Style packs (15 packs / 9 families)

The source of truth is each pack's `meta.yaml → profile`, injected into the kernel when a style matches. Packs marked ★ have a `grammar.yaml` learned from a corpus (deterministic grammar generation; the Studio style drop-down lists only these).

| Family | Packs |
|--------|-------|
| academic | fugue, piano-prelude |
| classical | classical-sonata, piano-sonata ★, string-quartet ★, symphony ★ |
| dance | mazurka, waltz |
| folk | british-folk-tune ★, celtic-jig |
| jazz | swing-standard ★ |
| pop | pop-standard ★ |
| romantic | chopin-piano ★ |
| sacred | chorale ★ |
| vocal | madrigal ★ |

Dimensions are defined in `skills/composition/genre/taxonomy.yaml`.

## Command reference (Studio chat / command line)

Commands can be mixed with natural language, several per line.

| Command | Description |
|---------|-------------|
| natural language | Describe the piece; a style pack is matched automatically. Explicit tempo/metre/key **go straight to the score**; the genre only suggests, never overrides |
| `/style 雨夜钢琴` | Bind a style pack (injects `meta.yaml → profile`) |
| `/skeleton [style]` | Purely deterministic skeleton, **no LLM** (set the style with `/style` first) |
| `/interpolate <A> <B> [t]` | Style interpolation / parametric style synthesis (**no LLM**; t=0 leans to A, t=1 to B; 0–1 or 0–100%) |
| `/refine [style]` | Closed-loop style-fidelity refinement (**no LLM**; seed branching + knob coordinate ascent maximising `style_overlap`; a deterministic DPO analogue, fully auditable) |
| `/import <MusicXML path>` | MusicXML round-trip import + recheck (**no LLM**; rechecks parallel fifths/octaves, duration completeness, range and style overlap, then re-exports normalised MusicXML + MIDI) |
| `/chords [key] [progression]` | Chord-progression advisor (**no LLM**; pure harmonic logic: diatonic legality, root motion, circle of fifths, leading-tone resolution, SATB realisation, parallel fifth/octave check) |
| `/render [piano\|gm] [reverb 0-0.9] [velocity <preset>] [<font.sf2>]` | Rendering (**no LLM**; performance layer only): SoundFont + convolution reverb + velocity curves; **never changes the score** |
| `/batch [pack/family...]` | Batch pipeline (**no LLM**): enumerate packs → N deterministic skeleton scores each → style fidelity → `runs/batch_report.md`/`.csv` |
| `/groove [on\|off] [swing] [humanize]` | Deterministic humanisation on MIDI export/playback (velocity jitter, micro-timing, swing); score unchanged |
| `/fugue full\|auto\|off` | Fugue control (`full` = whole fugue; `auto` = LLM decides from the brief, none if not mentioned; `off` = forbidden) |
| `/system 板腔\|曲牌\|拉格\|序列` | Systems layer (deterministic, bypasses the functional-harmony kernel): banqiang, qupai, raga, twelve-tone |
| `/key Am` `/tempo 72` `/meter 3/4` `/bars 16` `/voices 2\|3\|4` | Parameter tweaks |
| `/advice` | Analyse the current score and only suggest changes |
| `可以` / `执行` / `/apply` | Rewrite the piece following the last suggestions |
| `/continue` `/extend [n]` `/develop` `/variation` `/harmonize` | Continue / extend / develop / vary / harmonise |
| `/orchestrate [instr.]` `/transpose C` `/shorter` `/longer` `/simplify` `/complexify` `/rewrite` | Orchestrate / transpose / length / complexity / rewrite |
| `/learn-score chorale` | Learn the current score into a **style pack** (edits `meta.yaml`) |
| `/analyze` | Evaluation report (notation section + three metrics) |
| `/export` | Export the current score (MusicXML / MIDI) |
| `/demo` | Demo piece when no API is configured |
| `/help` `/new` `/clear` `/config` | Help / new piece / clear / configure |

`/help <command or feature>` shows one entry, e.g. `/help /chords`. Help text is generated from the single source `help_doc.py` and **always matches `runs/help.md`**.

## Score editor (visual staff editing + suggestions + live checking)

Click "✎ Edit" in the transport bar to edit the rendered staff directly, much like an AI code editor:

**Editing**
- Tools: select / ♪ note / 𝄽 rest / ⌫ erase; click on the staff to insert (the x coordinate picks the insertion point)
- Drag a note to change its pitch; `↑↓` step, `Shift+↑↓` octave, `1-5` duration, `r` rest, `.` dot, `#`/`b` accidentals, `s`/`a`/`t` staccato/accent/tenuto, `Del` delete, `Ctrl+Z/Y` undo/redo (60-step snapshot stack)
- Edits are written back to MusicXML after a debounce, keeping the analysis report and exports consistent

**Suggestions (AI-completion style)**
- Hovering shows a translucent ghost note and a candidate bar ranked by "leading-tone resolution > step > tonic/dominant arpeggio > repetition", each with a musical reason; click to insert. Durations are clamped to the remaining measure capacity

**Three-level live checking (lint-like)**
- 🔴 Hard block: measure overflow, out-of-range notes — rejected on input
- 🟠 Strict check (optional): parallel fifths/octaves (onset-aligned), leaps beyond an octave — blocked while editing; existing scores only get yellow hints to avoid noise
- 🟡 Warning: chromatic notes, edge-of-range notes — yellow badge

Layers: `music_score/editor_core.py` (pure logic, no Qt), `editor_ui.py` (toolbar/suggestion bar), `exporter.py` (model → music21). Slurs/ties are not yet editable and are lost when edits are written back.

## Subsystems

### Deterministic kernel `compose_kernel.py`
- `derive_subseeds` derives 7 sub-seeds from the main `seed`; `rng_for(dim, *parts)` gives branched random sources so melody, fugue and narrative are independently reproducible.
- Soft weights `_weighted_choice` / `_rhythm_weights_for` tune rhythm continuously by attribute (uniform/rest/long_start/short_end/dense/sparse) instead of discrete templates.
- `st.fugue_roles` + `spec['fugue_roles']`: fugue roles (subject/answer/countersubject/episode/middle-*/stretto/pedal/cadence).
- Section-level modulation: `set_harmony` takes optional `key_sharps`/`mode`, recorded in `spec['key_changes']`.
- Piano grand staff: two-voice piano outputs `parts[].staff` + `spec['staff_groups']` (brace).

### Notation layer `notation.py`
- `spell_name(tonic_pc=)`: raised leading tone in minor; modulating scores are spelled per measure key.
- `RuleLog`: per-rule counts (spelling / stem / beams / articulation / layout / rehearsal).
- `spec_to_music21` produces measured streams via `makeMeasures`, with metre changes, section key changes, grand staves and explicit tempo marks.

### Style routing `style_routing.py`
- Two-level routing: family + Chinese synonyms → pack, normalised confidence.
- `route()` / `route_or_raise()` / `explain()`; `strict=True` raises `StyleRoutingError` (with candidates and family hints) instead of failing silently.

### Evaluation and fingerprints `evaluate.py`
- `style_vector` (16-D) → `pack_fingerprint` (3 seed samples ⊕ corpus, cached in `<pack>/fingerprint.json`).
- Cross-pack z-score normalisation (`Z_CLIP=3.0`).
- Metrics: `style_overlap` (cosine), `style_rank` (top-1–3 hit), `attribute_adherence`, `nearest_neighbor` threshold 0.995.
- `evaluate_report(spec, ...)` backs `/analyze`.

### Systems layer `systems.py`
- Four deterministic systems that produce a spec directly (no functional-harmony assumptions):
  - `banqiang` (Chinese opera couplet phrases with metre changes)
  - `qupai` (Chinese tune-suite with syllable-slot filling)
  - `raga` (mode · tala cycle with a sustained drone)
  - `serial` (twelve-tone P/R/I/RI)
- `build_system(kind, **kw)` / `SYSTEM_LABELS` / `list_systems()`.

### Delivery `deliver.py`
- `score_to_lilypond` / `export_lilypond`: built-in `.ly` writer (works without a LilyPond binary).
- `render_pdf`: renders a PDF if LilyPond is installed (`brew install lilypond`).
- `archive_run`: archives a generation to `runs/<timestamp>-<title>/` (spec.json / score.musicxml / score.mid / score.ly / pdf / report / manifest).

## Score → Skill (corpus learning)

Learn **compositional technique** (not the notes themselves) from MusicXML and write it **straight into a style pack**:

```bash
python -m score_learning learn scores/corpus/bach_chorales_10 \
  --family sacred --pack-id chorale --genre 众赞歌 --no-llm
```

Output: `skills/composition/genre/packs/<family>/<id>/{meta.yaml, features/*.json, empirical_statistics.json, EMPIRICAL_SKILL.md}`.
See [`score_learning/README.md`](score_learning/README.md) and [`skills/composition/README.md`](skills/composition/README.md).

## Dependencies (summary)

PyQt5, music21, PyYAML, plus playback/synthesis libraries (see `requirements.txt`). Playback uses FluidSynth if configured, otherwise the system GS Wavetable synth.

## Project layout (core)

```
score_studio.py       GUI (chat composition + score editing + style browser + systems layer)
llm_compose.py        chat/command parsing + kernel orchestration + notation
compose_kernel.py     deterministic kernel (sub-seeds / soft weights / fugue roles / modulation / grand staff)
notation.py           notation layer (spelling / rule log / measures / key changes)
i18n.py               interface language switching (Chinese / English)
music_score/          staff editor (models / renderer / editor_core / editor_ui / exporter / interaction / audio_engine)
style_routing.py      two-level style routing
style_skeleton.py     style skeleton (profile → script call sequence)
evaluate.py           style fingerprints + three metrics
systems.py            systems layer (banqiang / qupai / raga / serial)
deliver.py            LilyPond export + runs/ archive
narrative.py          narrative generation
studio_daw.py         style/system browser widgets
skills/composition/   style packs + task skills (source of truth)
score_learning/       corpus → skill learning
tests/                kernel / round-trip / help / report-consistency tests + editor self-test
scripts/demos/        small playback and score-writing demos (play_*, make_g_major_score)
scripts/dev/          one-off maintenance and replay scripts (not used by the app)
scripts/eval/         soundfont comparison, blind-review export, texture checks
docs/                 design documents, review material, survey reports
```

Scripts under `scripts/` resolve paths from the repository root and can be run from anywhere, e.g. `venv/bin/python scripts/eval/check_texture.py --ab`.

The code and data for RAS-FR (statistical discovery of four-part voice-leading constraints) are published separately at [github.com/tyrone1979/ras](https://github.com/tyrone1979/ras); this repository no longer contains `score_learning/induction`, `diagnostics`, `dcra` or their tests.

### Tests

```bash
python -m pytest tests/ -q                              # full regression
python tests/test_prompt_to_report.py                   # prompt → score → report consistency (65 assertions)
python tests/score_editor_selftest.py                   # editor rules/suggestions/controller/round-trip (54 assertions)
```

`test_prompt_to_report.py` can also run the real LLM pipeline with `COMPOSE_E2E_LLM=1` (skipped by default; no API needed).

## Positioning (brief)

- **AIVA** (closest commercial product): we match its in-DAW editing with visual staff editing, suggestions and live checking, and differ by being deterministic and auditable.
- **Magenta Studio** (closest feature list): we add its Groove (micro-timing) and Interpolate (motif morphing) ideas.
- **NotaGen** (closest academic work): we follow its style-fidelity optimisation (rule checking + style match).
- **Suno / Udio etc.**: generate audio, not scores — a different track.
