# 统一学习命令 `/learn-all`

> 一条命令跑完三条学习流水线，编译成统一规则入库，`/compose-grammar` 直接可用
> 日期：2026-10-04

---

## 一句话

```bash
/learn-all          # GUI/对话里
```
```bash
venv/bin/python -m score_learning.relation.learn_all     # 命令行
```

**全量 10 个阶段 17 秒完成**，产出报告 `runs/relation/learn_all_report.md`。

---

## 一、三条流水线

| # | 阶段名 | 学什么 | 产出 |
|---|---|---|---|
| 1 | `chorale` | 巴赫众赞歌 350 首 | `sacred/chorale/grammar.yaml` |
| 2 | `leadsheet:<体裁>` × 8 | folk / jazz / pop / madrigal / sonata / strings / symphony / chopin | 各风格包 `grammar.yaml` |
| 3 | `relation` | Weimar 人工段落标注 456 首 | 各包 `form.form_plan` |

第 1、2 条产出**和声 / 旋律 / 节奏规则**；第 3 条产出**段落结构 + 段间关系**
（引用 / 承接 / 对比 / 递进）—— 正好补上 `plan_form` 缺的那部分。

三者最终都写进同一批 `grammar.yaml`，`/compose-grammar` 只读这一个文件。

## 二、用法

### 对话里

```
/learn-all                                    # 全量三条
/learn-all --skip chorale --skip leadsheet    # 只补关系学习
/learn-all --style jazz pop                   # 只学爵士和流行
/learn-all --dry-run                          # 只看会发生什么，不写盘
```

### 命令行

```bash
venv/bin/python -m score_learning.relation.learn_all
venv/bin/python -m score_learning.relation.learn_all --skip chorale --skip leadsheet
venv/bin/python -m score_learning.relation.learn_all --dry-run
venv/bin/python -m score_learning.relation.learn_all --help
```

参数与 `argparse` 兼容，`/learn-all` 内部用 `shlex.split` 解析同一套参数。

## 五、关键设计：编排层不改内核

三条流水线的入口都是现成的公开函数，统一层只做**编排 + 报告**：

```python
grammar.learn.learn(pieces)                → grammar.script.save(sc)
leadsheet.analyze.analyze_style(style)    → leadsheet.learn.learn(pieces, style)
leadsheet.learn.learn(pieces, style)       → leadsheet.script.save(sc, style)
relation.RelationExtractor.extract_solo() → compile_form_plan → inject_form_plan
```

好处：
- 单独跑某条流水线的老命令（`/learn-grammar jazz`）**完全不受影响**
- 某阶段失败不影响其他阶段（每个 Stage 独立 try/except，报告里标❌ 并附 traceback）
- 新增流水线只需在 `learn_all()` 里加一个 `run_xxx()`

## 六、两个实测踩到的坑

### 1. 元数据字段变了（静默取到 0）

第一版报告里所有子风格都显示「训练 0 / 留出 0」：

```python
'train': (v.get('meta') or {}).get('train')      # ← 旧字段
```

`learn_core` 重构后元数据移到 `sub['pieces'] = {'train': 56, 'heldout': 10}`，
`sub['meta']` 已不存在 → **`.get('train')` 静默返回 None，`or 0` 变成 0**。
这类「字段改名后静默取默认值」最难发现，已改用正确路径并加测试。

### 2. 干跑时不能引用未定义变量

```python
ev = (sc.get('evaluation') if not dry else None) or {}   # sc 在 dry 时未定义
```

`--dry-run` 会在 `sc` 赋值前就短路，抛 `UnboundLocalError`。
已把评估读取全部放进 `if not dry:` 分支。

## 九、已知限制

1. **`strings` 体裁只有 190 首**（其他体裁 198-908），子风格里有 2 个调式
   规则模型差于一元基线 —— 语料不足，非代码问题。
2. **非爵士体裁没有 form_plan** —— Weimar 标注只覆盖 8 种爵士体裁，
   民谣/流行/古典仍走 `templates` 老逻辑。
3. **全量重写 grammar.yaml** —— 每次 `/learn-all` 都会重写全部风格包
   （首次会生成 `.bak`）。若只想补关系，用 `--skip chorale --skip leadsheet`。
4. **`prune_reverted` 比例偏高**（jazz 8 个调式里 6 个回退）——
   说明剪枝阈值 `CTX_MIN=3` 对多数体裁偏激进，值得后续调参。
