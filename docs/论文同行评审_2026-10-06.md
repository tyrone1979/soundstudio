## 一、创新性与贡献是否成立

### P1（重大）核心贡献"一份工件同时被生成器和检查器读取"未与 Ebcioglu/CHORAL 充分区分
**位置**：§1 Contributions 第 1 条（lines 84–85）、§7 "Comparison with hand-coded ES"（line 607）、§2.3 Provenance（line 114）。

**问题**：贡献 1 的实质主张是"生成所依据的规则集与判分所依据的规则集是同一个对象，因此违例可以按规则号追责"。但 Ebcioglu (1988) 的 CHORAL 本身就是 generate-and-test：同一套 200+ 手写规则既参与生成又参与测试；Pachet & Roy (2001) 的约束模型同样"约束即模型"。稿件自己也承认与 CHORAL 的差别只剩"固定种子下的确定性"和"逐拍规则归因"（line 607），这两点相对"同构性"主张而言太弱。

**可能导致拒稿的理由**：ESWA 审稿人会直接写"the claimed isomorphism is standard practice in rule-based ES since the 1980s; the authors have not established what is new"。创新性存疑是拒稿的第一理由。

**修改建议**：
- 把"新"从"同构"这一层挪到可验证的那一层。稿件其实已经有一个硬证据——**修改 YAML 里存储的阈值会改变检查器的判决**（§3.3.2, line 209），而且有测试断言。把它从"代码里有测试"提升为一个**带数字的正式实验**：例如编辑 `hard_rules[R04].param`，报告在留出 Bach 与系统草稿上违例计数从 a 变到 b。这是同行可复核的、CHORAL 时代不存在的性质（CHORAL 的规则是写死在程序里的，不是可编辑数据）。
- 明确写出与 CHORAL 的三点可证伪差异：(i) 软知识是语料习得而非手写；(ii) 阈值以数据形式存放在规则条目内，检查器从那里读（CHORAL 无法"改一条规则的阈值"）；(iii) 目录可枚举（2 302 条）并公开索引。
- 相应地把 Contribution 1 的表述从"one artefact is read by both"改为更窄、更硬的"an edit to a stored threshold provably changes the checker's verdict, and the catalogue is enumerable"。

### P2（一般）标题/关键词声称 knowledge acquisition，§6 又自我降级为 aggregation
**位置**：标题、keywords、§6 "How much of the system rests on human labelling"（line 602）。

**问题**：稿件在第 602 行诚实地说"we describe the procedure as knowledge *aggregation* ... rather than knowledge *acquisition* in the sense of Gaines & Shaw (1993), whose procedures include verification against an authority"。但标题、关键词、RQ 表述仍用 knowledge acquisition。这是**框架层面的自我矛盾**，审稿人会抓。

**修改建议**：二选一——(a) 标题改为 "corpus-aggregated" 并在 §1 交代为何不称 acquisition；或 (b) 保留 acquisition，但在 §6 补一句"我们保留该术语，同时明确指出本流水线缺少 Gaines & Shaw 意义上的权威校验环节，故该术语在此为弱义"。不要像现在这样两处各说各话。

### P3（一般）"可审计/可解释"没有可操作的对照
**位置**：§1、§2.3、Contributions。

**问题**：全文把 auditability/explainability 当作核心卖点，但除"能枚举规则号"外，没有任何对照实验显示"规则号归因"带来的具体收益（例如，教师定位错误所需时间、学生修复成功率）。稿件把这类实验推给了未来工作，这是合理的scope 声明，但**卖点与证据不匹配**会被审稿人记为 overclaim。

**修改建议**：在 §1 的 "What is deliberately not claimed" 里再补一句：本文所谓 auditable 仅指"可枚举、可编辑、违例可追责到规则号"，**不含**"可解释性带来教学收益"的实证。

### P4-b（已完成）终止式类型分布实验已跑完，结论推翻了论文原来的假设
**背景**：上一轮把"cadence match 被 R11 钉住"的替代指标写成"终止式类型分布"，但**数据一直缺失**，只指出了方向。作者已授权补跑。

**做了什么**：新增 `score_learning/grammar/cadence_type_dist.py`（零侵入——R11 关闭臂靠给 `_phrase_states` 传空公式实现，不改 `compose.py`），产物 `runs/experiments/e3_cadence_type.json`，测试 `tests/test_cadence_type_dist.py`（11 项）。三臂配对（同一批种子）：留出巴赫 / 完整草稿 / R11 关闭；另报 C 规则池类型分布与"仅内部句"子集；TVD 置信区间按**曲目**重抽样。

**结果（写入 §5.3 与新增 Table `tab:cadtype`，两版论文已改）**：

| 指标 | 大调 | 小调 |
|---|---|---|
| TVD 草稿 vs 巴赫 | 0.216 [0.149, 0.330] | 0.202 [0.155, 0.382] |

### P5（重大）无约束对照组改变的不止一个变量，且正文有一句自相矛盾
**位置**：§5.2 Setup（line 447）与 Results（line 451）；`kernel_baseline.py:51–74`；`e2_kernel_baseline.json`。

**问题**（已回查代码与产物）：
- 对照实际做了三件事：`NEG = 0.0`（DP 转移层硬约束失效）、`HARD_CONSTRAINTS = False`（候选集构造层硬过滤失效，7 处 `continue`）、`max_tries=1, accept_any=True`（关闭 accept/reject 门）。
- 后果：`out_of_grammar` 从 **0.00 升到 0.59**，和声困惑度从 4.59 升到 300.67。也就是说对照组不只是"关掉硬规则"，而是**同时放开了语法词汇过滤**。稿件称"the constraint set is the only variable"（line 447 同一句里又承认门也关了），自相矛盾。
- 更严重的一句（line 451）：*"The same accept/reject gate that is inert on the constrained system ... is what rejects all twenty unconstrained ones."* ——门在对照组里**已被关闭**（`accept_any=True`），不可能"拒绝"任何东西；0/20 clean 是**检查器的判决**，不是门的行为。这句是事实性错误。

**可能导致拒稿的理由**：这是全篇被引用最多的对比（摘要、highlights、结论都写 445 vs 0）。一旦审稿人发现对照构造与文字描述不符，会怀疑整个 RQ2。

**修改建议**：
- 改 Setup 为："control differs in the constraint layer *and* in the retry gate; we show the retry gate is inert on this corpus (all constrained drafts accepted at attempt 1, `e2_attempts.json`), so the confound is benign; the residual difference in `out_of_grammar` (0.00 → 0.59) means the control should be read as 'the search without the rule layer', not 'the search without R01–R09 only'."
- 删掉或重写 line 451 那句关于 gate 的因果表述。
- 若能做到，补一条**只关硬规则、保留词汇过滤**的中间臂（保留 `HARD_CONSTRAINTS=True` 但把 R01–R09 的代价置零），把 out_of_grammar 钉在同一水平，对照就干净了。

### P6（重大）"no false positive" 是同义反复，不应作为 headline 结论
**位置**：摘要、highlights 第 6 条、§5.6（lines 556, 577）、Table 8。

**问题**（已回查 `e6_fault_injection.json`）：`false_positive_on_clean = 0`，但 `base_clean = 20` 的 20 份草稿**本身就是这个检查器接受出来的**（accept/reject 循环保证零违例）。一个检查器对"自己刚判定为干净的输入"不报违例，是逻辑必然，不是经验发现。

**可能导致拒稿的理由**：摘要和 highlights 都把"zero false positive"当卖点，审稿人会指出这是 circular，进而怀疑作者对实验设计的判断力。

**修改建议**：
- 把 FP 定义改为**独立负例**：(i) 用留出 Bach 的**合法片段**（人工确认无违例的片段）测 FP；(ii) 用另一路生成器（如自训 HMM 采样）的草稿测 FP；(iii) 至少把"零 FP"改述为"零 FP on drafts the checker itself accepted — a definitional, not an empirical, result"。
- 摘要/highlights 里删掉 "with no false positive"，改为 "recovers 56 of 58 injected faults (R01/R03/R06)"，把精度数字留在正文表里。

### P7（重大）故障注入只覆盖 3/9 条检查规则，却给出"the checker"的整体结论
**位置**：§5.6（lines 556, 579）、Table 8。

- 稿件的**方法论诚实度是显著加分项**——主动声明不主张什么、主动报告四个对自己不利的结果（JM 优于 KN、剪枝阈值随估计器移动、复杂度预算无效、**终止式类型分布也不独立于 R11**）、主动承认零违例与零 FP 的构造性、主动承认终止式标注的循环性。这在当前投稿环境里是稀缺品质，也是我认为它**不应被拒稿**的主要理由。
- 但**可复现性链条目前是断的**（P17 仓库未建、P18 补充材料矛盾、P19 语料缺失）。这三项不修，任何认真负责的审稿人都无法给"接受"。
- **数字口径**（P11、P12）与**创新性论证**（P1）是决定最终能否被接受的第二个门槛。

**拒稿风险最高的三条**（若返修中未解决）：**P18**（补充材料 learn 命令复现不出论文数字，且与主文三处矛盾）、**P11**（Table 2 数字跨协议不自洽，易被解读为挑数）、**P26**（摘要/highlights/keywords 三项全超，技术审查即退回）。P17 调整为"投稿前必须完成"，P30 已在本轮修掉，均不再是本轮最高风险。
